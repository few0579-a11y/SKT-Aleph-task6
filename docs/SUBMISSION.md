## 짧은 확인 방법

**① 어디로 가나요**
새 시크릿 창에서 https://skt-aleph-task6.vercel.app 을 엽니다.

**② 세 단계 안에 무엇을 하나요**
1. 계획 목록에서 **「일본어 회화: 면접 대비 2주」**를 누릅니다.
2. 위쪽 **「회고 보기 →」**를 누르고, 집계 숫자 하나(예: 계획 수)를 누릅니다.
3. 맨 위 **「전체 데이터 내보내기(JSON)」**를 누릅니다.

**③ 무엇이 보이면 통과인가요**
- 모든 화면 맨 위에 노란 안내 문구 「지금은 로그인이 없어 …」가 보입니다.
- 1단계: 계획의 수정 이력(v1 = 최초 계획)과 할 일 목록, 「정렬 기준: 마감일 오름차순 → 같으면 ID 오름차순」이 보입니다.
- 2단계: 숫자 아래 근거 표가 열리고 「집계 값 n = 근거에서 계산한 값 n ✓ 일치」가 초록색으로 보입니다.
- 3단계: `pds-export-….json` 파일 하나가 내려받아집니다.

**④ 안 될 때는 무엇이 보이나요**
- 화면에 「오류: 서버 오류가 발생했습니다」가 보이면 서버가 DB에 연결하지 못한 것입니다.
- 「불러오는 중…」에서 멈추면 API 요청이 실패한 것입니다.
- 근거 표 위에 빨간 「✗ 불일치」가 보이면 집계와 근거 기록이 서로 맞지 않는 것입니다.

## 제출문

### ① AI에게 맡긴 일
- 내가 정한 설계(데이터 항목, 이력 보존 방식, 정렬·필터 규칙, 중복 완료 방지 방식, 집계 규칙)에 맞춰 DB 스키마·API·화면 코드를 작성
- 로컬 임시 DB로 통과 기준별 자동 검사 작성·실행, 실제 화면에서 버튼·폼 동작 확인
- Supabase SQL 실행, GitHub 저장소 생성·푸시, Vercel 프로젝트 설정(비밀값 입력 제외) 등 배포 작업
- 증거 화면 캡처, 스키마 계약 파일과 대조 스크립트, 보안 점검 스크립트 작성
- 배포 후 요청이 멈추는 문제(DB 연결 재사용) 원인 추적과 수정
- 회고 #1의 개선점 문장과 계획 #2의 예상 시간 제안(이후 개선점과 예상 시간은 내가 다시 정해 회고 #2·계획 #3을 만들었다)
- 제출문 ②③을 내가 대화에서 고른 내용을 바탕으로 정리(내용은 내가 확인해 확정)

### ② 내가 직접 판단한 일
- 이전에 AI가 혼자 만든 코드를 쓰지 않고 지운 뒤, 카드마다 선택지를 보고 직접 고르며 처음부터 다시 만들기로 했다.
- 실제 계획으로 자격증 공부 대신 일본어 회화(면접 대비)를 골랐고, 하루 4시간을 면접 대본 120분·원어민 대화 30분·교재 90분으로 나눴다. 기간은 2주(11/12~11/25), 우선순위는 높음.
- 성공 기준을 자기소개 1분, 예상 질문 5개 막힘 없이 답하기, 원어민 대화 10회로 정했다.
- 할 일을 결과 단위로 8개로 나누고(대화·교재는 주차별), 할 일 합계와 맞추려고 계획 예상 시간을 3360분에서 3240분으로 수정했다(이력에 v1이 남음).
- 기술·설계: Vercel + Supabase(서울), 브라우저는 서버 함수로만 DB 접근, 계획 이력은 DB 트리거, 할 일은 소프트 삭제, 정렬·필터는 서버에서 ID 보조 정렬, 완료는 멱등성 키 + 유니크 제약, 실행 기록은 추가만 가능, 회고는 계획 전체 + 주차별로 정했다.
- 다음 계획은 같은 구성을 이어 가되 예상 질문을 10개로 늘리고, 자격증 공부와 병행하려고 우선순위를 보통으로 낮췄다.

### ③ AI 제안을 따르지 않은 일 (없다면 그 이유)
- 계획: AI는 자격증 공부 하나를 추천했지만 일본어 회화를 골랐다.
- 성공 기준: AI는 "자기소개 3분" 하나만 두자고 했지만, 하루 4시간 중 절반만 면접 대본이라 기준과 시간이 맞지 않는다는 점을 내가 짚었고, 자기소개를 1분으로 줄이고 예상 질문 5개·대화 10회를 넣었다.
- 증거 화면: AI는 검색과 필터를 각각 찍자고 했지만 한 화면에 함께 찍기로 했다.
- 진행 방식: AI가 처음에 혼자 이미 있던 코드를 검증하고 넘어가려 했을 때 멈추게 하고, 선택지를 보고 직접 고르는 방식으로 바꿨다.
